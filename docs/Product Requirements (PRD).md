# Product Requirements (PRD)

# 1. Product Vision

AI-first застосунок для планування задач. Основний сценарій:

**Brain Dump → AI аналізує думки користувача → формує задачі → визначає пріоритет, тривалість і дедлайн → генерує план на сьогодні.**

Усі задачі в системі народжуються виключно через AI-флоу (Brain Dump). Ручне створення задачі в обхід AI не передбачено — це принципове рішення, що визначає AI-first позиціонування продукту.

---

# 2. Екрани MVP

1. **Auth** — реєстрація / логін
2. **Brain Dump** — введення тексту з клавіатури або голосом (диктування), обробка AI, чорнові картки задач
3. **Today's Plan** — задачі на сьогодні
4. **Calendar** — задачі на майбутні/інші дні
5. **Drafts** — невирішені чернетки задач (статус `draft`), очікують дії користувача (confirm/edit/delete)
    - **Task Detail** — не окремий екран, а модальне вікно (відкривається з Today's Plan / Calendar)

---

# 3. Основний User Flow

## 3.1 Вхід у застосунок

- **Перший вхід** (немає жодної задачі) → одразу **Brain Dump**
- **Наступні входи** (є задачі на сьогодні) → **Today's Plan**; Brain Dump доступний окремою дією

## 3.2 Виклик Brain Dump

- Доступний у будь-який момент через **FAB (floating action button)** на Today's Plan і Calendar
- Користувач вводить текст із клавіатури або диктує голосом
- Після завершення вводу — кнопка **"Далі"**
- AI обробляє весь текст цілісно (не в реальному часі під час набору)

## 3.3 AI-обробка та чорнові задачі (Review)

- AI генерує чорнові картки задач з тексту
- AI **враховує контекст** вже підтверджених задач на відповідний день (не працює ізольовано від існуючого плану)
- Усі чорнові картки відображаються одразу (не по одній)
- Кожна картка: поштучні дії **Confirm / Edit / Delete**
- Кнопка **"Confirm remaining"** — підтверджує всі непочеплені (не редаговані й не видалені) картки

### AI-попередження (неблокуючі)

Генеруються в момент створення/підтвердження задач (під час Review):

1. **Перевантаження дня** — якщо сумарна тривалість (підтверджені + чорнові задачі дня) перевищує 8 год
2. **Конфлікт часу** — якщо задачі перетинаються за часом початку. Застосовується **лише до задач, які мають запланований час**; задачі без часу не беруть участі у перевірці конфліктів.

Попередження лише інформують, не блокують підтвердження. Розв'язання конфлікту — повністю на користувачі; система дозволяє існування задач з однаковим/перетинаючимся часом.

## 3.4 Незавершені чернетки

- Якщо користувач залишає Review-екран, не підтвердивши/не видаливши картку — вона зберігається як **draft** (нічого не губиться)
- Усі чернетки доступні у вкладці **Drafts**

# 4. Картка задачі

Поля картки:

- **Назва**
- **Опис**
- **Пріоритет** (бадж)
- **Запланована дата** (пікер, обов'язкова)
- **Запланований час** (пікер, необов'язковий)
- **Тривалість**

## Правила заповнення полів

- Якщо параметр (пріоритет, тривалість, дата/час) явно чи неявно випливає з тексту користувача — AI заповнює поле автоматично
- Якщо AI не може визначити пріоритет/тривалість — AI все одно пропонує значення за замовчуванням, позначене як **"AI suggestion"** (користувач може прийняти або змінити в один клік)
- **Запланована дата — AI завжди проставляє її при генерації чорнової задачі**: з тексту, якщо вона вказана/випливає з контексту, або дефолт "сьогодні", якщо ні
- **Поле дати не може бути порожнім на рівні UI** — користувач може лише змінити дату на іншу через пікер, але не очистити його до порожнього значення. Тому дата присутня завжди, без винятків
- **Запланований час не є обов'язковим полем**. Якщо час не випливає з Brain Dump — AI залишає поле часу порожнім. На відміну від пріоритету/тривалості, для часу не використовується дефолтне значення чи позначка "AI suggestion". Користувач може додати, змінити або прибрати час у будь-який момент, поки задача не має статусу `done` (див. правило read-only для done у розділі 5)

---

# 5. Статуси задачі

**draft → confirmed → done**

- Користувач може зняти галочку "done" назад (повернення в `confirmed`)
- **Today's Plan**: чекбокс "виконано" — прямо на компактній картці, без відкриття модалки
- **Calendar**: позначити "виконано" можна лише в модальному вікні (розгорнута картка)

### Правило read-only для done

Якщо `status = done` — усі поля задачі повністю **read-only**: неможливо редагувати title/description/priority/duration/date, недоступний drag&drop, недоступне видалення. Розблокування відбувається лише через зняття чекбокса виконання (`done → confirmed`).

### Відображення за статусом

- **Today's Plan**: done-задачі лишаються видимими, автоматично групуються **внизу списку**, без можливості змінити порядок (order недоступний, бо задача read-only)
- **Calendar**: done-задачі **не відображаються**

---

# 6. Drag & Drop

- **Today's Plan**: задачі можна перетягувати між собою (реордер) — стосується лише активних (draft/confirmed) задач
- **Calendar**: задачі можна перетягувати в межах дня (реордер) і на інший день (зміна дати)
- Done-задачі недоступні для drag&drop (read-only)

---

# 7. Drafts

Окрема вкладка для всіх задач у статусі `draft` — головне призначення: жодна чернетка, залишена непідтвердженою після Brain Dump, не губиться.

Оскільки поле дати не може бути порожнім на рівні UI (AI завжди проставляє дату), практично всі чернетки тут вже мають дату. Вкладка залишається місцем для невирішених чернеток загалом, а не спеціально для задач без дати.

Сортування: **найновіші зверху**.

Дії:

- Поштучне **Confirm / Edit / Delete** (як на Review-екрані)
- **Confirm All** — підтверджує масово всі чернетки з їхніми поточними датами (дата не змінюється при масовому підтвердженні)
- **Delete All**

---

# 8. Видалення задач

- Доступне звідусіль (Today's Plan, Calendar, Drafts, модалка) — **крім** задач у статусі `done` (read-only)
- Механіка: **миттєве видалення з undo-тостом** (кілька секунд на відновлення)
- Той самий механізм undo застосовується і до **Delete All**

---

# 9. Прострочені задачі (MVP-рішення)

Для MVP — **пасивне візуальне маркування**: прострочені задачі (дата в минулому, не `done`) підсвічуються в Calendar, без автоматичного трекінгу чи перенесення.

Track/лічильник overdue-задач у MVP **не входить**.

---

# 10. Авторизація

**Способи входу в MVP:**

- Email + пароль
- Google OAuth

**Об'єднання акаунтів:** один email — один акаунт, незалежно від методу першої реєстрації. Якщо користувач зареєструвався через email+пароль, він також може залогінитись через Google з тим самим email і навпаки (і навпаки) — обидва методи ведуть до того ж акаунту, без конфлікту чи дублювання.

**Post-MVP:** відновлення паролю (forgot password)

---

# 11. Загальні технічні/нефункціональні вимоги

**Хостинг:** застосунок має легко хоститись на **Vercel** — це впливає на вибір технологічного стеку (нативно для Vercel — Next.js/React).

**Платформа:** веб-застосунок з переважним акцентом на мобільні пристрої (mobile-first), з підтримкою **PWA** (можливість встановити на головний екран телефона, повноекранний режим). PWA не конфліктує з Vercel-хостингом — стандартна комбінація (маніфест + service worker поверх звичайного веб-застосунку).

**Верстка:**

- **Mobile-first, адаптивна** верстка за замовчуванням — один layout, що коректно розтягується на більші екрани без втрати якості
- **Окремий desktop-specific UX** запроваджується тільки точково, де це доречно покращує досвід користувача (наприклад, інша взаємодія з drag&drop чи густіші елементи керування) — без штучного відокремлення заради принципу

**Мова інтерфейсу:** тільки українська в MVP (мультимовність — post-MVP).

**Тема (адаптивна до часу доби):** дизайн застосунку візуально змінюється залежно від поточного часу доби користувача — **4 стани: ранок / день / вечір / ніч**. В MVP тема визначається **виключно автоматично** (без ручного перемикача від користувача).

**AI-провайдер:** **Google Gemini Flash**. Обгрунтовано через простоту підключення та вартість: безкоштовний тариф без потреби вводити картку та без терміну дії, достатній для обсягу MVP/демо.

# 12. Today's Plan (деталізація)

## Компактна картка задачі

У списку без відкриття модалки видно:

- Назва
- Час початку
- Скорочений опис (1-2 рядки, ellipsis)
- Бадж пріоритету
- Тривалість
- Чекбокс "виконано"

## Сортування

- **Початковий порядок:** спочатку задачі із зазначеним часом — у хронологічному порядку за часом; після них — задачі без часу, у порядку їх згадування в Brain Dump (AI зберігає цей порядок у масиві результату, сервер записує його через `sort_order`)
- Drag&drop дозволяє користувачу вручну відхилитись від цього порядку — після ручного reorder `sort_order` стає джерелом фактичного порядку й **не перераховується автоматично при кожному рендері**
- **Нова підтверджена задача** (через новий Brain Dump або confirm з Drafts) вставляється в список за тим самим початковим правилом: задача з часом — у відповідну хронологічну позицію серед задач з часом; задача без часу — в кінець групи задач без часу. Після вставлення `sort_order` задач дня переобчислюється; раніше встановлений вручну порядок інших задач при цьому не втрачається за межами точки вставки

# 13. Backlog / Post-MVP ідеї

- Відновлення паролю (forgot password)
- Налаштування (Settings) з можливістю визначати період трекінгу невиконаних задач (за замовчуванням трекінг вимкнено)
- Автоматичне перенесення прострочених задач
- AI-нагадування про невиконані задачі при новому Brain Dump
- Авто-пропозиція розв'язання конфлікту часу від AI
